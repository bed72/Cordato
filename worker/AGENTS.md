# Cordato — worker Node-RED

- Serviço independente, sem alterações implícitas no Flutter ou PocketBase.
- Escopo: Node-RED 5.0.9 / Node.js 24 e flow importável de áudio → Gemini → despesa PocketBase, sem bibliotecas adicionais. Não confundir código versionado com implantação/homologação ou integração do Flutter.
- Documentação em português. Não adicionar comentários ao código, `var` ou identificadores chamados `result`.
- Editor e Admin API exigem autenticação. Não criar senha padrão, acesso anônimo ou fallback que desabilite autenticação/criptografia.
- Não ler, imprimir, versionar ou sobrescrever segredos. `.env.example` contém somente exemplos; valores reais pertencem ao ambiente privado local/Dokploy.
- Preservar `/data`, flows e credenciais. A imagem semeia `flows.json` somente quando ausente; nunca sobrescrever automaticamente ou apagar volumes para atualizar.
- Versionar flows após exportação e revisão. Não versionar `*_cred.json`, backups, logs ou dados pessoais.
- Flows importáveis ficam em `flows/<nome>/flows.json`, com README próprio e exportação completa da funcionalidade. `worker/flows.json` continua como base inicial do container; não carregar exemplos automaticamente nem agregar/sobrescrever flows existentes.
- Áudio usa `flows/audio/audio.js` na imagem, exposto por `functionGlobalContext.cordatoAudio`. As funções visuais delegam etapas; transportes são nós HTTP nativos. Atualizar imagem, export, documentação e testes juntos. O root HTTP é `/api`, distinto do editor `/admin`.
- Uma despesa por áudio; ambiguidade/múltiplas despesas não geram escrita. Validar centavos inteiros seguros, categoria e data civil antes de criar. O owner vem somente do auth-refresh de users, nunca do cliente/modelo. Usar token do usuário nas regras nativas, nunca superusuário.
- Logs usam somente allowlist de ID de correlação, eventos, tempos, status, tamanho e códigos locais. Não registrar áudio, base64, transcrição, arquivo, tokens, chaves, usuário ou dados financeiros. Não conectar Debug à mensagem completa nem registrar erros remotos brutos.
- Falhas do Gemini podem incluir `diagnostic` somente como código local da allowlist, em `request.failed` na etapa de interpretação. Classificar detalhes em memória sem copiar texto/campos remotos para logs; fallback genérico não comprova causa específica. Preservar limpeza, limite de concorrência e ausência de segunda resposta após `202`.
- Sem retry de criação ou idempotência durável: perda de confirmação pode representar cadastro já realizado. Preservar `persistence_unknown` e os limites de upload/concorrência; desconexão não cancela automaticamente HTTP ou desfaz escrita.
- Áudio responde `202` após validar upload/configuração/sessão e continua em memória, sem fila persistente, polling ou notificação de conclusão. Reinícios podem perder trabalho aceito. Após aceite, desconexão não interrompe o processamento; manter vaga de concorrência até concluir/falhar e nunca emitir segunda resposta. Falhas posteriores aparecem somente nos logs seguros.
- Não instalar módulos pela paleta ou Function sem tarefa explícita. Dependências futuras exigem versões fixadas na imagem.
- Não executar deploy, push, build, containers ou mudanças remotas sem autorização específica.
- Verificações desta pasta: `node --check settings.js`, `node --test test/*.test.js`, `sh -n docker/entrypoint.sh`, `shellcheck docker/entrypoint.sh` e `git diff --check`.
- Com Docker disponível, validar os dois pares Compose usando `config --quiet` e variáveis fictícias; nunca imprimir configuração resolvida com segredos reais.
- Registrar bloqueios. Testes de configuração não comprovam login, HTTPS, persistência em containers, deploy ou integração de áudio.
